# 개발 작업 지시서

이 저장소를 고치는 사람(개발자·AI 도우미)이 먼저 읽는 문서입니다.
제품이 **무엇을·왜** 하는지는 PRD에, **어떻게 고치고 확인하는지**는 이 문서에 적습니다.

## 1. 가장 중요한 원칙

> **컴퓨터를 잘 모르는 교사가 구글 계정 하나로, 10분 안에, 혼자 끝낼 수 있어야 한다.**

기능을 더할 때마다 아래를 지킵니다.

1. **쉬운 방법(주소로 여는 전시관)에 가입·설치·비밀번호·접근 키를 요구하지 않는다.**
2. 교사가 보는 화면에는 영어 용어(토큰, 배포, 환경 변수, 저장소…)를 쓰지 않는다. 고급 영역 안에서만 쓴다.
3. 교사가 틀릴 수 있는 곳은 화면이 **직접 확인해서** 무엇을 어떻게 고칠지 알려 준다. (예: 시트 공유, 사진 폴더 공유)
4. 한 화면에서 끝낸다. 다른 사이트로 보내야 하면 새 창 버튼과 "거기서 누를 것"을 함께 적는다.
5. 서버·빌드 도구·npm 패키지를 늘리지 않는다. 정적 파일(HTML·CSS·JS)만으로 동작해야 한다.

## 2. 두 가지 운영 방식

| | 쉬운 방법 (기본) | 고급 방법 |
|---|---|---|
| 교사가 하는 일 | 구글 설문지 → 만들기 화면에서 주소 만들기 | Vercel 배포 + GitHub 접근 키 |
| 호스팅 | 원본 저장소의 GitHub Pages 한 곳을 모든 학교가 함께 씀 | 학교마다 Vercel 프로젝트 |
| 설정이 있는 곳 | **주소 뒤의 값** (`?s=시트ID&t=제목…`) | `js/config.js` (GitHub Actions가 고침) |
| 사진 | 구글 서버의 축소본을 바로 불러옴 | `assets/art/`에 축소 저장 가능 |
| 관련 코드 | `js/link.js`, `js/setup.js`의 `make()` | `api/update-images.js`, `.github/workflows/*`, `tools/*` |

## 3. 파일 지도

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 전체(첫 화면, 만들기 화면 `#setupModal`, F9 관리 `#dataModal`) |
| `js/config.js` | 기본 설정. 고급 방법에서 `tools/apply-config.mjs`가 **정규식으로 고치므로 줄 모양을 바꾸지 말 것** |
| `js/link.js` | 주소의 값을 읽어 `ART_CONFIG`를 덮어씀. 주소 만들기(`ArtLink.build`) |
| `js/data.js` | 구글 시트 읽기(CSV) → 학생·작품·학급. `LS`(기기 저장소) |
| `js/setup.js` | 만들기 화면: 시트·사진 확인, 주소·QR 만들기, (고급) 저장 |
| `js/app.js` | 앱 본체: 첫 화면, 3D 관람, F9 관리 |
| `js/multi.js` | 함께 관람: 아바타, 대화, 실시간 연결 |
| `js/auto.js` | 자동 관람: 입구로 걸어가 작품을 무작위로 차례로 감상 |
| `js/lobbyart.js` | 로비 소장품: 빈 벽을 찾아 큰 그림을 걸고 조형물을 놓음 (`assets/lobby/*.jpg`) |
| `js/post.js` | 후처리: 빛 번짐 · 색 보정 · 비네팅 (화질 높음·초고해상도) |
| `js/world.js` `architecture.js` `decor.js` `textures.js` `museums.js` | 3D 미술관 |
| `api/update-images.js` | (고급) Vercel 서버 기능 → GitHub Actions 실행 |

스크립트는 `index.html` 맨 아래 순서대로 읽힙니다. `link.js`는 반드시 `config.js` 다음, `data.js` 앞입니다.

## 4. 전시관 주소 규칙 (`js/link.js`)

| 값 | 뜻 | 검사 |
|---|---|---|
| `s` | 구글 시트 ID (**있으면 주소 모드**) | 영문·숫자·`_-` 20~80자 |
| `gid` | 시트 탭 번호 | 숫자 |
| `t` `t2` | 전시 제목 첫째·둘째 줄 | `<>` 줄바꿈 제거, 30자 |
| `sub` `n` `p` | 부제 · 학교 이름 · 기간 | 위와 같음 |
| `g` | 학교 로고의 구글 드라이브 파일 ID | ID 모양만 허용 (임의 주소 금지) |
| `h` | 감상평 Apps Script 주소 | `https://script.google.com/…/exec` 모양만 허용 |
| `m=0` | 함께 관람(아바타·대화) 끄기 | |
| `c=0` | 대화만 끄기 | |
| `auto=1` | 미술관에 들어가면 자동 관람 시작 (TV·전자 칠판용, `#seoul` 과 함께) | |
| `make` | 만들기 화면을 바로 엶 | |

- **이미 나눠 준 주소가 깨지면 안 됩니다.** 값의 이름과 뜻을 바꾸지 말고, 새 기능은 새 이름으로 더합니다.
- 주소의 값은 누구나 바꿀 수 있는 **믿을 수 없는 입력**입니다. 화면에 넣을 때는 `textContent` 또는 `esc()`를 쓰고, 주소로 받은 값을 `src`·`href`·`fetch`에 그대로 넣지 않습니다.
- 주소 모드에서는 `C.linkMode`, `C.noServer`, `C.storeKey`가 켜집니다. 한 사이트를 여러 학교가 쓰므로 `LS`가 저장 이름 뒤에 `@시트ID앞16자`를 붙여 학교별로 나눕니다. **`localStorage`를 직접 쓰지 말고 `ArtData.LS`를 쓰세요.**
- 서버가 필요한 화면 요소에는 `class="server-only"`를 붙입니다(주소 모드·GitHub Pages에서 숨겨짐).

## 4-1. 함께 관람 (`js/multi.js`)

- **연결 방식**: 공개 MQTT 중계 서버 3곳에 웹소켓으로 동시에 붙어 같은 내용을 보내고, 받는 쪽이 보낸 사람별 순번(`q`)으로 겹친 것을 버립니다.
  브라우저끼리 직접 연결(WebRTC·Trystero)은 시험에서 상대를 찾고도 연결에 실패했고(`peer-connect-failed`), 학교 와이파이(기기 간 차단·TURN 없음)에서 같은 문제가 나기 쉬워 쓰지 않습니다.
- **방**: `구글 시트 ID + 미술관 ID`. 같은 전시의 같은 미술관에 있는 사람끼리만 보입니다.
- **암호화**: 방 이름에서 만든 AES-GCM 키로 모든 내용을 암호화하고, 토픽 이름도 해시입니다. 전시관 주소를 모르는 사람(중계 서버 포함)은 내용을 읽을 수 없습니다. 단, **주소를 아는 사람은 누구나 들어올 수 있고 이름을 사칭할 수 있으므로** 본인 확인이 필요한 기능을 이 위에 만들지 마세요.
- **메시지**: `s` 소개(이름·아바타·위치, 3초마다) · `p` 위치(움직일 때 초당 5번) · `c` 대화 · `q` 소개 부탁 · `b` 나감. 10초 동안 소식이 없으면 나간 것으로 봅니다.
- **받은 값은 모두 믿을 수 없는 입력**입니다. 이름·대화는 `cleanName`/`cleanText`(길이 제한 + 비속어 가림)를 거쳐 `textContent`와 캔버스 글자로만 그립니다.
- 공개 중계 서버는 무료 시험용이라 **가용성 보장이 없습니다.** 연결이 안 되면 혼자 관람으로 조용히 넘어가야 하며, 관람 자체를 막으면 안 됩니다. 중계 서버 목록은 `BROKERS`.
- 자기 아바타는 그리지 않습니다(1인칭). 한 방 최대 60명(`MAX_PEERS`).

## 4-2. 자동 관람 (`js/auto.js`)

`enter`(입구로 걷기) → `move`(다른 전시실 입구로 장면 전환) → `walk`(작품 앞까지 걷기, `app.glide` 사용) → `view`(7초 감상) → 다음 작품.
길 찾기가 없으므로 전시실 사이는 걷지 않고 장면을 전환합니다. 키보드·마우스·조이스틱·미니맵을 건드리면 `stop()`.

## 4-3. 화면 품질 (`js/world.js` · `js/post.js` · `js/lobbyart.js`)

| 화질 | 무엇이 켜지나 |
|---|---|
| 낮음 (휴대폰 기본) | 그림자·후처리 없음 |
| 높음 (컴퓨터 기본) | 해 그림자 + 실내 그림자 + 로비 반사 + 후처리. **처음 150장 동안 속도를 재서 초당 24장보다 느리면** 후처리와 실내 그림자를 자동으로 끔 (`app.lightMode`) |
| 초고해상도 | 위 + 4096 그림자 + 작품별 실제 스포트라이트 |

- **실내 그림자**: 천장 바로 아래(`IN_LIGHT_Y`)에서 아래로 비추는 빛 하나가 관람객을 따라다닙니다. 지붕·천장은 빛보다 위에 있어 그림자에 들어가지 않습니다. `finishInterior()`가 건물 안의 불투명한 물체에 `castShadow`를, 바닥에 `receiveShadow`를 켭니다.
- **반사**: 짓기가 끝나면 로비 한가운데에서 큐브맵을 한 번 찍어 실내 재질(`zone: 'in'`)의 환경맵으로 씁니다. 실내 재질은 반드시 `w.M({ zone: 'in' })`으로 만드세요.
- **로비 소장품**: 미술관마다 로비 모양이 달라, 후보 벽에 빛줄기(raycast)를 쏘아 "평평하고 비어 있고 앞에 가구가 없는 벽"일 때만 겁니다. 걸 벽이 모자라면(원형 로비 등) 자립 벽을 세웁니다. 로비 구조를 고치면 12곳을 모두 찍어 확인하세요.
- 로비 그림은 Canva에서 이 전시관용으로 새로 만든 것입니다. 실제 작가·작품을 흉내 낸 그림으로 바꾸지 마세요. 설명 판에 "전시관을 위해 새로 만든 그림"이라고 적혀 있어야 합니다.
- 미니 지도는 **위쪽이 미술관 안쪽(−z)** 입니다.

## 6. 고친 뒤 확인하는 법

빌드가 없습니다. 폴더에서 정적 서버만 띄웁니다.

```
python -m http.server 8765
```

| 확인 | 방법 | 기대 결과 |
|---|---|---|
| 문법 | `node --check js/파일.js` | 오류 없음 |
| 첫 화면 | `http://localhost:8765/` | 예시 작품, "우리 학교 전시관 만들기" 배너 |
| 만들기 화면 | `…/?make` | 화면이 바로 열림. 공개된 시트 주소 → ✅ 연결 → 주소와 QR이 나옴 |
| 주소 모드 | 만든 주소를 새 탭에서 열기 | 제목이 바뀌고 배너가 없음. F9 화면에 비밀번호·사진 업데이트 칸이 없음 |
| 3D 입장 | 주소 끝에 `#seoul` | 미술관이 열리고 콘솔에 빨간 오류가 없음 |
| 함께 관람 | 같은 주소 + `#seoul` 을 창 두 개로 열고 각각 이름·아바타 고르기 | 서로의 아바타·이름표가 보이고, 👥 숫자가 2, 대화가 양쪽에 뜨고 말풍선이 나옴 |
| 대화 끄기 | 주소에 `&c=0` / `&m=0` | 대화 칸이 없음 / 👥 버튼도 없음 |
| 자동 관람 | ▶ 자동 관람 누르기, 또는 주소에 `&auto=1#seoul` | 입구로 걸어가 작품을 차례로 보여 줌. 화면을 누르면 멈춤 |
| 나쁜 입력 | `…?s=(ID)&n=<b>x` | 꺾쇠가 지워져 글자로만 보임 |
| 휴대폰 | 브라우저 폭 375px | 만들기 화면이 한 줄로 쌓임, 가로 스크롤 없음 |

`index.html`의 `?v=숫자`는 캐시를 지우는 번호입니다. JS·CSS를 고치면 모든 `?v=`를 1 올립니다.

## 7. 올리기

- `main`에 올리면 GitHub Pages(쉬운 방법의 공용 사이트)에 1~2분 안에 반영됩니다. **모든 학교의 전시관이 함께 바뀌므로** 6번 표를 다 확인한 뒤 올립니다.
- 고급 방법으로 복사해 간 학교의 저장소는 바뀌지 않습니다.
- `.github/workflows/`를 고치면 `api/update-images.js`의 `installWorkflows()`가 원본에서 받아 가는 파일도 바뀝니다.
